# convx と Qhull、CGAL、Rust のクレートの比較

これは報告であり、テストではない。実行した行はすべて載せている。他のライブラリのほうが速い行、小さい行もそのまま載せている。以下に、達成・未達成の判定はない。CGAL と Qhull に対するクレート自身の判定は、[verification.md](verification.md) のパリティ計測である（ADR 0006）。これは閾値を持つ決まった行の集合で、結果を動かしうる変更のたびに取る。この報告はリリースごとに一度、より多くのデータとライブラリで取り、何も判定しない。

2026-10-14 に、convx の `71b3069` で取った。すべての数値は [bench/summary.json](bench/summary.json) にある。

| システム | Windows 11、WSL2、Ubuntu 22.04.2、カーネル 5.15.133.1 |

| C++ | g++ 11.4.0、`-O3 -DNDEBUG`。GMP 6.2.1 |

| ライブラリ | 版 | 演算 |
| --- | --- | --- |
| convx | `71b3069` | `f64` の入力から、すべての述語の符号を厳密に決める |
| CGAL | 5.4 | `f64` 上の厳密な述語（D = 2、3 は `Epick`、それより上は `Epick_d`） |
| Qhull | 2020.2 | 浮動小数点。許容誤差の内にあるファセットはまとめる |
| `spade` | 2.15.1 | 厳密な述語 |
| `delaunator` | 1.1.0 | 頑健な orientation。等しい点はまとめない |
| `delaunay` | 0.8.2 | 厳密な述語 |
| `parry3d-f64` | 0.31.1 | 浮動小数点 |
| `geo` | 0.33.1 | 頑健な orientation |

方法は [benches/compare/README.md](../benches/compare/README.md)、行は [benches/compare/rows.txt](../benches/compare/rows.txt) にある。

- **時間**は、各ライブラリの出力の構築を、そのライブラリ自身のプロセスの中で計ったものである。ファイルの読み込みは含まない。一つの行のライブラリは、ラウンドごとに交代で走る。convx の最初の構築が 1.5 秒未満なら 3 回の構築を 5 ラウンド、そうでなければ 1 回を 3 ラウンドである。Qhull はプロセスごとに一度構築し、自身の「CPU seconds to compute hull (after input)」を報告する。表は中央値と、括弧の中に convx の中央値に対する比を示す。1 より大きければそのライブラリは convx より遅く、1 より小さければ速い。
- **ピークメモリ**は、ファイルを読んで一度構築するプロセスの常駐セットのピークで、3 回の中央値である。カーネルの `ru_maxrss` を GNU time で読んだ。プロセス全体の値なので、ファイルから読んだ点はどのライブラリでも含まれる。
- **時間に沿ったメモリ**は、そのようなプロセス一つの常駐セットを 2 ms ごとに読んだものである。

各ライブラリが計測区間で作る出力は同じではない。それも比較の一部である。

- **convx**：`build()` が返すもの。凸包なら、頂点、頂点の一覧と隣を持つファセット、そして入力の各点の分類（頂点、境界上の点、内部点、重複点）。三角形分割なら、隣を持つ単体。
- **CGAL**：凸包の表面と、三角形分割のセルと隣を平らな配列に書いたもの（CGAL が持つ範囲で convx と同じ出力）。
- **Qhull**：頂点で表したファセットを、ファイルに書いたもの。
- **Rust のクレート**：それぞれ自身の構造（アダプタは `benches/compare/rust/` にある）。

## 各ライブラリにあって他にないもの

- **次元。** convx はすべての次元で凸包と三角形分割を作る（ここでは D = 2〜8）。CGAL と Qhull も同じである（ここでは D = 2〜8）。`spade`、`delaunator`、`geo` は D = 2 だけ、`parry3d-f64` は D = 3 だけ、`delaunay` は D = 2〜5 である。
- **厳密さ。** convx、CGAL、`spade` は厳密な符号で決める。同じ点に対して、同じ頂点とファセット、同じ単体と隣を返す。Qhull と `parry3d-f64` は浮動小数点であり、頂点、ファセット、サイトを少なく返すことがある（下の数を参照）。
- **論理ファセット。** convx のファセットは、厳密に同じ超平面にある単体をまとめたものである。格子の立方体はファセット 6 枚になる。CGAL は D = 3 では三角形（12 枚）を返し、凸包の頂点が 16 個の D = 4 の格子では 5,904 個を返す。Qhull は許容誤差の内にあるファセットをまとめる。厳密に同一平面上にあるものもまとめ、ほぼ同一平面上にあるものもまとめる。
- **同一球面上のサイト。** convx と CGAL は、同じ球面上にあるサイトのグループを単体に分割する。Qhull はグループを一つの領域として返す（D = 2 の格子で、Qhull は正方形 9,801 個、convx と CGAL は三角形 19,602 個）。
- **入力のすべての点の行き先。** convx の出力は、入力の各点が何になったか（頂点、境界上の点、内部点、どの点の重複か）を示す。これは convx の計測区間に入っていて、他のライブラリにはない。
- **落とされるサイト。** Qhull の Delaunay 三角形分割は、他に近すぎると判断したサイトを出力に入れない。10^5 個の Kuzmin のサイトのうち、出力にあるのは 57,938 個である。

### 他のライブラリのほうが速いところ

- **凸包。** 凸包の 42 行のうち 16 行で、他のライブラリが最も速い。Qhull が速いのは、`cube` D3 の 10^6（0.90）、`sphere` D3 の 10^4 と 10^5（0.92 と 0.98）、`sphere` D5（0.98）、D = 3 と 4 の格子（0.97 と 0.43）、D3 の Plummer（0.87 と 0.63）、Dragon と Buddha のスキャン（0.92 と 0.81）である。CGAL は D = 2 の格子（0.38）と、10^5 と 10^6 の Kuzmin の点（0.50 と 0.38）で速く、10^7 では遅い（7.01）。`geo` は `cube` D2 の 10^6（0.83）と Kuzmin の点（0.59 と 0.55）で速い。`parry3d-f64` は `cube` D3（0.89 と 0.97）と Plummer（0.50 と 0.82）で速い。
- **Delaunay。** Delaunay の 38 行のうち 26 行で CGAL が速い。10^6 点未満の D = 2〜4 のほとんどの行で 0.85〜0.99、D = 2 の格子で 0.67、D3 の 10^6 点の `cube`、球の中の一様分布、Plummer で 0.87〜0.88、四つのスキャンで 0.85〜0.89 である。`cube` D5 の 10^4 では同じ（1.00）である。Qhull は D4 と D5 の 10^3 点のファイルで速い（0.91）。`spade` と `delaunator` は、入っている D = 2 のすべての行で速い（0.55〜0.89）。ただし 10^6 個の Kuzmin のサイトでは `delaunator` が遅い（1.08）。
- **メモリ。** 凸包の 42 行のうち 37 行で、Qhull のメモリが最も少ない。D = 2 の三角形分割では、`spade` と `delaunator` は convx の 56%〜59% のメモリを使う。10^6 と 10^7 個の Kuzmin のサイトでは、Qhull の三角形分割は convx の 3 分の 1 と 5 分の 1 のメモリを使い、大半のサイトを落とす。

### convx のほうが速いところ

- **凸包。** 凸包の 42 行のうち 26 行で、convx が最も速い。差が大きいのは、D ≥ 4 の CGAL に対して（`cube` で 2.6〜22 倍）、D2 の球面上の点の Qhull に対して（9.6〜19 倍）、D3 の球面上の点の `parry3d-f64` に対して（2.9 倍と 29 倍）である。
- **Delaunay。** convx は CGAL より、D = 2 の 10^6 個のサイト（1.19〜1.26）、D3 と D4 の球面上の点（1.10〜2.84）、D = 3 と 4 の格子（1.10 と 1.56）、10^7 個の Kuzmin のサイト（1.44）で速い。Qhull より、D4 と D5 の 10^3 点の 2 ファイルを除くすべての Delaunay の行で速い。
- **メモリ。** convx の三角形分割は、格子（88%〜94%）を除いて CGAL のピークの 53%〜75% を使い、D3 の 10^4 点以上のファイルでは Qhull の 29%〜56% を使う。

## 比較しなかったもの

- **D = 5 の `delaunay` クレート。** 1,000 点の 3 回の構築を行う一つのプロセスが、81 分たっても終わらなかった。この行は `delaunay` クレートを除いて取った。D = 2〜4 では、1,000 点に 0.46 秒、3.7 秒、135 秒かかった。
- **比較しなかったクレート**（#599 のオーナーの決定）：`qhull`（Qhull へのバインディングで、Qhull 自身がここにある）、`chull`、`tritet`、`startin`、`voronoice`、`voronator`。
- **Voronoi 図。** 同じ出力を作るライブラリが、ここには他にない。convx の図は、Delaunay 三角形分割と、頂点ごとの線形方程式の解である。
- **スレッド。** ここでは、どのライブラリも一つのコアで走らせた。CGAL には並列の三角形分割がある。convx の構築は逐次である。
