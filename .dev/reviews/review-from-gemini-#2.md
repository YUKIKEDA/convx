『convx 設計仕様』に対するレビュー結果を報告します。

全体として、「厳密幾何述語によるトポロジー決定」「完全決定論（逐次と並列の一致）」「任意次元対応」という極めて高い堅牢性を目指した優れた設計書です。特にオイラー標数の整合性検査や、アフィン次元退化の報告仕様などは非常に精緻に定義されています。

一方で、**実装段階で確実にブロッカーまたは設計矛盾となる重大な論点**がいくつか存在します。以下に優先度順に指摘と改善提案をまとめました。

---

### 1. 最重要課題：厳密幾何述語の実現手段と依存関係の矛盾

#### ① 依存クレートに厳密演算ライブラリが存在しない
- **現状**: 依存関係は `faer`, `rayon`, `pulp`, `thiserror` のみ（第9節）。
- **問題**: 
  - $D \le 3$（あるいは $D \le 4$）であれば Shewchuk のような浮動小数点拡張（adaptive precision expansion）を自前実装することも現実的ですが、$D \ge 5$ の任意次元行列式の厳密符号判定には任意精度整数（BigInt）または有理数型によるガウス消去・Bareiss アルゴリズム等が必要です。
  - `ExactEvaluationExhausted` をエラー定義に置いていることからも任意精度へのフォールバックを想定しているようですが、標準ライブラリ（`std`）と上記4クレートだけでは高次元の厳密符号計算が実装できません。
- **改善案**:
  - `num-bigint` などの多倍長整数クレートを依存に追加するか、自前で `Expansion`（Shewchuk 方式の任意精度拡張浮動小数点）をどこまで実装するのかスコープを明記してください。

#### ② 「向き判定を Householder QR で行う」という記述の矛盾
- **現状**: 「$D \le 4$ の向きは専用式で計算する。それ以外の法線と、専用式を持たない次元の向きは、Householder QR（`faer`）で計算する」（第1節）。
- **問題**:
  - **向き（orientation）は行列式の符号そのもの**です。Householder QR 分解は直交化過程で丸め誤差が蓄積するため、QR 分解から得られる符号は厳密述語（多項式の厳密符号）にはなりません。「誤差は式の評価における丸めに限る」「フィルタ誤差上界を超えないときは厳密符号に落とす」という第1節の設計原則と矛盾します。
- **改善案**:
  - **法線ベクトル（単位ベクトル）の近似計算**には Householder QR を使用する。
  - **向き（orientation）判定**は、一貫して「$(D+1) \times (D+1)$ 行列式の符号（$D \le 4$ は手動展開のフィルタ付き述語、$D \ge 5$ は LU/ガウス消去フィルタ＋任意精度フォールバック）」と定義を切り離してください。

### 2. アルゴリズムとトポロジーの論点

#### ① ファセットマージのタイミング（インクリメンタル vs 事後）
- **現状**: 第5節でマージ条件が詳述され、第6節で並列 Quickhull が記述されています。
- **問題**: 
  - Quickhull の途中で共面ファセットをマージするのか（Qhull の pre-merge / post-merge 方式）、それとも**「構築中はすべて単体（Simplex）のまま Quickhull を完走させ、最終出力時に共面単体を論理ファセット（LogicalFacet）へまとめる」**のかが読み取れません。
  - 構築中に非単体ファセットを扱う場合、ホライズン探索やトポロジー変異の計算量が跳ね上がり、並列コミットの予約条件（$T(P) \cap T(Q) = \emptyset$）の維持が極めて難しくなります。
  - 一方で、「厳密述語」を使うのであれば、同一平面上の点は外側に出ない（距離が厳密に 0 以下になる）ため、構築中に微小な非凸が発生して破綻することはありません。
- **改善案**:
  - 「構築中の Quickhull コアは**純粋な単体複体（Simplicial Complex）**として扱い、全点の挿入が完了した後の最終段階で同一平面上の隣接単体を `LogicalFacet` へマージする」方針であることを明記することを強く推奨します。

#### ② 境界上点の「凸結合判定」アルゴリズムの具体化
- **現状**: 第3節で「現在の面の極点集合の凸結合で表せない点は、その論理ファセットの頂点に加える。表せる点は `coplanar_points` に入れる」とあります。
- **問題**: 
  - ある点が $(D-1)$ 次元の凸多胞体の頂点集合の凸結合で表せるかどうかの判定は、低次元では 2D/3D の点-多角形内外判定ですが、高次元では一般に線形計画問題（LP）または面に対する局所凸包の再計算になります。
- **改善案**:
  - 外側点の取り込み順によって極点が決まるため、「その面（$(D-1)$ 単体群）に対する $(D-1)$ 次元 Quickhull を局所的に行う」のか、あるいはどのような代数的判定を行うのか、計算手法の指針を追記してください。

#### ③ Delaunay の垂直ファセット（$n_{D+1} = 0$）の厳密判定
- **現状**: 下側包を $n_{D+1} < 0$ で定義（第7節）。
- **問題**: 
  - 入力点群の凸包境界上にある単体を放物面 $x_{D+1} = \|x\|^2$ に持ち上げた場合、持ち上げ空間でのファセット法線の最終成分が厳密に $0$（元の空間に対して垂直）になるケースがあります。
  - これを `f64` の法線ベクトルの値だけで判定すると、丸め誤差により垂直な面が誤って下側包に含まれ、射影時に体積 0 の潰れた Delaunay 単体が生成されるリスクがあります。
- **改善案**:
  - $n_{D+1} < 0$ の判定も、法線ベクトルの float 値を見るのではなく、元の $D$ 空間における頂点群の向き判定（determinant）と整合する述語として定義すべきです。

#### ④ Voronoi の非有界レイのトポロジー表現
- **現状**: `VoronoiRay` が `direction`（論理ファセットの外向き法線）を持つ（第8節）。
- **問題**: 
  - $D \ge 3$ において、Voronoi の非有界な境界はファセットの法線方向だけではありません。例えば 3D において「凸包のリッジ（辺）」を共有するサイト同士の境界面（Voronoi 2D-face）は非有界であり、その外向き方向は2つのファセット法線の間（扇状）に開きます。
  - 「Delaunay の面（$D-1$ 単体）の双対レイ」は外心の外向き法線で一致しますが、Voronoi セル（各サイトの領域）や境界面（Interface）に付くレイの方向が「論理ファセットの外向き法線」だけで過不足なく記述できるか再確認が必要です。

### 3. 並列化と決定論的再現性

#### ① 逐次版と並列版の出力完全一致
- **現状**: 「逐次版も、公開結果が並列版と一致するように点を処理する」（第6節）。
- **指摘**: 
  - 逐次版で「距離最大点を1点ずつ挿入して Outside set を更新」という古典的な Quickhull を実装し、並列版で「独立なバッチを組んで複数点コミット」を実装すると、点を取り込む順番が変わり、中間生成される単体やタイブレーク結果が乖離します。
  - **逐次版であっても並列版と全く同一のバッチ抽出・コミットスケジューラを単一スレッドで回す構造**に統一する必要があります。このアーキテクチャ方針を設計書に明記してください。

### 4. Rust 実装・API レベルの課題

#### ① `f64` の重複判定とソート
- **現状**: 「重複は `==` で判定する。`-0.0` と `+0.0` は同じ点である。`to_bits` では比べない。一致した点の代表は、最小の入力インデックスである」（第3節）。
- **実装上の注意**:
  - $N$ 点の重複を $O(N \log N)$ で集約するにはソートが必要ですが、`f64` は `Ord` を実装していません。
  - 標準の `f64::total_cmp` を使うと `-0.0 < +0.0` と判定されてしまい、同一点とみなされなくなります。
  - 事前処理として「`-0.0` をすべて `+0.0` に正規化してから `total_cmp` でソートする」等の具体的なアルゴリズムを指定しておくと、実装時のバグを防げます。

#### ② 静的 API の型安全性の補足
- **現状**: `[[f64; D]]` から `&[f64]` への変換に `as_flattened()` を使用（MSRV 1.80）。
- **評価**:
  - `slice::as_flattened` を用いることで安全かつゼロコストで変換できるため、非常に良い選定です。
  - 静的 API（`StaticConvexHull<const D: usize>`）において、`dim` の型パラメータ $D$ のチェックがコンパイル時に行える点も有用です。

### まとめ・改訂の推奨アクション

1. **第1節 / 第9節**: 
   - orientation は行列式の符号（Exact Predicate）とし、Householder QR は「幾何述語」ではなく「近似法線ベクトルの導出」に限定する。
   - 依存クレートに任意精度計算（または自前 expansion モジュール）の計画を明記する。
2. **第5節 / 第6節**: 
   - Quickhull 実行中は単体分割（Simplex Arena）を保ち、ファセットマージは完了後の後処理（Post-processing）として実行することを明確にする。
   - 逐次版と並列版が同一のバッチコミットパイプラインを共有することを明記する。
3. **第7節 / 第8節**: 
   - Delaunay の $n_{D+1} < 0$ 判定を幾何述語の枠組みに組み込む。
   - 高次元 Voronoi の非有界要素（レイ・境界）の幾何的定義を精査する。
