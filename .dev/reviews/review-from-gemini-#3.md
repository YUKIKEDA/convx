純 Rust による N 次元幾何計算ライブラリ `convx` の設計仕様書として、述語先行（predicates-first）の思想、決定性、インデックス仕様、並行性の非干渉条件などが非常に緻密に言語化されています。

実装フェーズで手戻りや未定義動作になり得る**「幾何アルゴリズムの整合性」「数値・述語の境界」「API・データ型の詳細」**の観点からレビューします。

## 1. 重大な論点（アルゴリズム・幾何学的整合性）

### (1) Quickhull における共面極点の取り残しと分類ロジックの矛盾
第3節および第5節の「距離ゼロ・共面点の取り込み」に関して、論理的な矛盾または曖昧さがあります。

* **問題点**:
  * Quickhull は通常、現在のアフィン包（ファセット）に対して**厳密に外側（距離 $> 0$）**の点のみを Outside set に入れ、可視ファセットを更新します。
  * 距離が厳密にゼロの点はファセットを可視化しないため、もし「点の挿入中は単体複体のまま進め、全点の挿入が終わったあとに距離ゼロの分類を行う」とすると、**初期単体のファセットと同一平面上にあるが外周を広げる点（共面極点）が凸包に取り込まれない**まま終わってしまいます（例: 正方形の4頂点のうち3頂点で初期三角形を作った場合、4点目は三角形の平面上にあり距離ゼロですが、正方形の極点です）。
  * 一方で第3節には「点がそのどの部分面に対しても厳密に外側でなければ `coplanar_points`、いずれかの部分面の外側ならその論理ファセットの頂点に加える」とあります。しかし、**全点取り込み後に既存面の外周を超える点が現れること自体、その時点の凸包が未完成である**ことを意味します。
* **推奨修正**:
  * 共面点（距離ゼロ）を「挿入をスキップして後から頂点昇格する」のではなく、**「距離ゼロの点が既存ファセットの $(D-1)$ 次元境界の外側にある場合は、通常の点と同様にそのファセット（またはリッジ）を更新する」**のか、あるいは**「初期単体の選定時点で極値（各軸の最小・最大点）を必ず含め、共面極点が Outside set から漏れないようにする」**のか、ライフサイクルを明確に定義してください。

### (2) 並列コミットにおける「非干渉バッチ」の判定条件
第6節の並行性制御について、提示されている条件は必要条件ですが、十分条件の判定手法が未定義です。

* **問題点**:
  * $T(P) \cap T(Q) = \emptyset$ かつ $H(P) \cap H(Q) = \emptyset$（可視面集合・ホライズン向こう側面集合・ホライズンリッジ集合の非交差）を満たしていても、$P$ を挿入して新たに張られたファセット群 $F_{\text{new}}(P)$ に対して、点 $Q$ が「外側」に見えてしまうケース（可視性の動的干渉）があり得ます。
  * 「同じバッチに残してよいのは、適用順を入れ替えても単体複体が一致する組だけである」と記されていますが、コミット前にこれをどう判定するかのアルゴリズム（例: $Q$ と $F_{\text{new}}(P)$ の幾何評価を投機的に行うのか、空間的なバウンディングボックス/セパレータを用いるのか）を固定する必要があります。

### (3) 全点共球（Co-spherical）時における Delaunay の「下側包」定義
第7節の「全体が共球で持ち上げが平坦なときも、サイト凸包の分割として成功する」について。

* **問題点**:
  * 全点が同一球面上にある場合、$x_{D+1} = \|x\|^2$ による持ち上げ点群は $R^{D+1}$ 内の単一の超平面に載ります。このとき持ち上げ包のアフィン次元は $D$ となり、通常の意味での「下側ファセット（法線の $x_{D+1}$ 成分が負）」が存在しません（表裏の区別がつかない、または法線の高さ成分が厳密にゼロ）。
  * 「サイト凸包の分割として成功する」とありますが、この退化時にどの向きを下側とみなして単体分割を構成するのか（例: 任意の初期単体を基準に空間内の向きを誘導する等）の縮退規則を1行補足する必要があります。

## 2. 幾何述語・数値カーネルの論点

### (1) SIMD 距離走査と厳密述語の不整合リスク
第1節に「SIMD の距離走査は Outside set を分ける速い経路として残す。走査で出た符号をトポロジーに使ってよいのは、その誤差上界を超えているときだけである」とあります。

* **懸念点**:
  * 平面方程式 $x \cdot n + \text{offset}$ の法線 $n$ と $\text{offset}$ は浮動小数（Householder QR）で計算された**近似値**です。
  * 一方、厳密な向き判定は元の頂点の**行列式述語（orientation）**で行われます。
  * 近似平面に対する浮動小数計算の誤差上界と、元の定義点群に対する行列式述語の誤差上界は代数的に異なるため、「近似平面からの距離は誤差上界を超えて正（外側）だったが、元の単体に対する orientation 行列式を厳密評価すると非外側（ゼロまたは負）になる」という不整合が境界近傍で起きる可能性があります。
* **推奨**:
  * トポロジー判定（可視ファセットの決定）に用いる述語は、常に単体の頂点インデックスに基づく `orientation(facet_vertices, p)` の符号とし、SIMD 距離走査はあくまで「確実に外側にある点（距離 $\gg \epsilon$）」を絞り込むための**フィルタ（枝刈り）**に限定する記述に統一するのが安全です。

### (2) 依存クレートと厳密演算の仕様
第1節で「自前のコードでも、依存リストにない追加クレートでもよい」とありつつ、第9節の依存関係は `faer, rayon, pulp, thiserror` に固定されています。

* **懸念点**:
  * フィルタをすり抜けた場合の「厳密評価（Exact arithmetic / Expansion）」をどう実装するかが宙に浮いています。自前で浮動小数展開（Shewchuk-style expansions）を組むのか、多倍長整数クレート（`dashu` や `rug` 等）を入れるのかでアーキテクチャの規模が大きく変わります。
  * 特に $D \ge 5$ では Shewchuk のような固定展開式の手書きは現実的でないため、任意次元行列式の厳密符号判定（例: 浮動小数フィルタ付き LU 分解 + 必要に応じたビッグインテジャーやバークレー方式の適応精度演算）を担う内部モジュールの設計指針を第1節に明記すべきです。

### (3) $D \le 4$ の専用式の展開規模
* $D=4$ の凸包ファセット（4-単体に対する法線/orientation）は **$5 \times 5$ 行列式**（120項）になります。
* $D=2$（$3\times 3$、6項）や $D=3$（$4\times 4$、24項）に比べ、$D=4$ の完全展開はコードサイズ・レジスタ圧力ともに跳ね上がります。専用式をコード生成するのか、小行列展開にするのか、実装工数を見積もっておく必要があります。

## 3. データ構造と API の詳細化

### (1) 欠番（Sentinel）の表現
`DelaunaySimplex` の定義：
```rust
pub struct DelaunaySimplex {
    pub vertices: Vec<u32>,  // 長さ D+1
    pub neighbors: Vec<u32>, // 長さ D+1。無ければ欠番
}
```
* **指摘**: `neighbors` の型が `Vec<u32>` ですが、「無ければ欠番」の表現が明記されていません。
  * `u32::MAX` を番兵とするのか、`Option<u32>` の配列（`Vec<Option<u32>>`）にするのかを明示してください。パフォーマンスとメモリの観点からは `u32::MAX`（`convx::INVALID_ID`）が一般的です。
  * また、入力点数が `u32::MAX` 以下とあるため、インデックス空間として `u32::MAX` が番兵と衝突しないよう「最大入力点数は `u32::MAX - 1`（または番兵として別の値）」と整合性を取る必要があります。

### (2) `boundary_cycle` の次元別挙動
```rust
pub fn boundary_cycle(&self, facet: usize) -> Option<Vec<u32>>;
```
「$D$ が 1, 2, 3 のときだけ定義される」とありますが、各次元で返される列の定義を明確にすべきです：
* $D=3$: 2次元ファセット（凸多角形）の外周頂点を、法線に対して右手系（反時計回り）で並べた巡回列（長さ $\ge 3$）。
* $D=2$: 1次元ファセット（線分）。端点2個の配列（長さ 2）。進行方向（外向き法線に合う向き）の順序。
* $D=1$: 0次元ファセット（端点）。頂点1個（長さ 1）。
* $D \ge 4$: 常に `None`。

### (3) 静的 API のシグネチャの欠落
第9節で「静的 API はスタック上の配列と単相化のためのラッパー」「静的凸包は $1 \le D \le 8$」と触れられていますが、肝心の型定義やシグネチャ例がありません。
* 例：`ConvexHullS<const D: usize>` や `convex_hull_fixed::<const D: usize>(points: &[[f64; D]]) -> ...` のようなシグネチャを記載しておくと、利用側の想定がブレません。
* `&[[f64; D]]::as_flattened()`（Rust 1.80 で安定化済み）を利用する方針は MSRV と合致しており適切です。

### (4) 辞書順最小な `spanning_points`
第3節で退化時に返す `spanning_points` について：
> 「長さは $\textit{actual\_dim} + 1$、辞書順で最小の列である」

* アフィン独立な点集合はマトロイド（アフィン擬マトロイド）を成すため、**昇順ソート済みの代表点列に対して先頭から貪欲（Greedy）に独立性を判定して採用していけば、得られる列は自ずと辞書順最小**になります。「昇順代表点からの貪欲抽出で得られる辞書順最小列」と記載しておくと、実装者が迷わずに済みます。

## 4. ドキュメント・命名の軽微な改善点

1. **`Simplex` 構造体の `group: GroupId`**
   * 第4節の `struct Simplex` 内に `group: GroupId` が登場しますが、`GroupId` 型の定義がありません（単なる `u32` のエイリアスか、世代付き ID か）。
2. **`VoronoiCell::rays` の整列**
   * 第8節の末尾でレイの並び順が「起点の番号、次いで `hull_facet` の辞書順」と定義されていますが、`hull_facet` は `Vec<u32>` なので「スライスの辞書順比較」であることが明確に伝わる記述にしておくと安全です。

### レビューまとめ
設計思想である「述語による厳密な符号決定」と「論理ファセットへの集約」は、浮動小数点幾何計算において最も破綻の少ない堅牢なアプローチです。
実装着手前に、**①共面極点の取り込みタイミング（Quickhull のライフサイクル）**、**②並列バッチの干渉判定条件の具体化**、**③厳密述語（フォールバック先）のライブラリ/アルゴリズム選定** の3点だけ仕様を確定・追記することをお勧めします。
