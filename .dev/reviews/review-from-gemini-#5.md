本設計仕様書（`convx-design.md`）は、「幾何述語の厳密性 $\to$ トポロジー判定 $\to$ 破壊的変異」という健全な順序を徹底しており、浮動小数点の丸め誤差による位相破綻を防ぐための思想が極めて明確に言語化されています。Euler 特性数による検証やバッチコミットによる決定論性の保証など、高品質な幾何ライブラリに不可欠な要件が的確に押さえられています。

実装フェーズで手戻りや未定義動作を発生させないために、**アルゴリズム上の不整合・曖昧な仕様・API の整合性**の観点から修正・明確化すべき点をレビューします。

---

### 1. アルゴリズムと幾何ロジックの不整合・未定義事項

#### (1) $D=1$ における `volume()` および単体頂点入れ替えの破綻
* **問題点**:
  セクション 5 に「末尾 2 点を入れ替えた外向き順で」とありますが、$D=1$ の場合、単体ファセットの頂点数は $D = 1$（1 点のみ）です。末尾 2 点が存在しないため、インデックス範囲外アクセス（パニック）となります。
* **推奨修正**:
  $D=1$ は特異ケースとして分岐を明記してください。
  - $D=1$ では頂点入れ替えは行わず、体積は $D=1$ 専用式 $|x_{\max} - x_{\min}|$ を直接使う。
  - $D \ge 2$ の場合にのみ「末尾 2 点の入れ替え」を適用する。

#### (2) 共面点（`coplanar_points`）の分類と頂点追加アルゴリズムの曖昧さ
* **問題点**:
  セクション 3「インデックスの分割」にある「距離ゼロの面での外側判定」について：
  > 「リッジの内側にある頂点を $a$ とする。点 $p$ がそのリッジの外側にあるのは、$\mathrm{orient}(\mathrm{ridge}, p, q)$ と $\mathrm{orient}(\mathrm{ridge}, a, q)$ の符号がどちらもゼロでなく、互いに逆のときである。」
  
  論理ファセット $V$ は一般に単体ではなく任意の多面体です。多面体ファセットにおける「リッジ」の列挙方法、およびリッジに対して「内側にある頂点 $a$」をどう選ぶかが定義されていません。単体ならリッジ（$D-1$ 点）に対して残りの頂点 $a$ は 1 点に確定しますが、多胞体の場合は一意になりません。
  また、「外側なら `vertices` に入れ、外側だった面すべての頂点集合に加える。頂点を加えた面は、同じ外側判定で分割を取り直す」という再帰的な凸包構築の手順が抽象的です。
* **推奨修正**:
  - 面内の単体分割（triangulation）を基準に判定するのか、面ごとの $(D-1)$ 次元凸包を解くのかを明記する。
  - 射影基底を作らず $D$ 次元の orientation 述語で行う場合、「ファセットを構成する現在の単体分割のうち、境界リッジ（共有相手が共面でないリッジ）に対して $a$ をその単体の対向頂点とする」といった具体的な幾何学的定義を与える必要があります。

#### (3) Delaunay：全点共球時のサイト凸包計算の依存関係
* **問題点**:
  セクション 7 で、全点が共球（持ち上げた点が平坦）のときは pulling triangulation でサイト凸包内部を分割するとあります。このとき「サイト凸包の境界面」が必要になりますが、Delaunay 内部から通常凸包ルーチンを呼ぶのか、それとも $D$ 次元の凸包を前もって解いているのかが記述されていません。
* **推奨修正**:
  「全点共球を検知した場合、内部的に元の $D$ 次元サイトに対して `ConvexHullBuilder`（またはその内部コア）を呼び出して凸包境界を取得し、その境界面に対して pulling triangulation を再帰適用する」旨を処理フローとして明確化してください。

#### (4) Voronoi 頂点まとめと持ち上げ凸包ファセットの対応関係
* **問題点**:
  セクション 8 で「有限な Voronoi 頂点は、持ち上げて同一超平面に載る Delaunay 単体を、推移的に一つへまとめたもの」と記述されています。
  幾何学的には、これは**「持ち上げ空間（$D+1$ 次元）における下側凸包の同一論理ファセット」**と 1 対 1 に対応します。
* **推奨修正**:
  「Voronoi 頂点のクラスタリングは、$D+1$ 次元の論理ファセットのグルーピングそのものである」と明記すると、Voronoi の構築ロジックが凸包の論理ファセット統合処理を完全に再利用できることが明確になり、実装の簡潔化と信頼性が向上します。

#### (5) `VoronoiRay` の方向と起点の定義
* **問題点**:
  「方向は、その論理ファセットの外向き単位法線である」とありますが、ここでいう「論理ファセット」が「元空間（$D$ 次元）の凸包ファセット」であることが文章上やや紛らわしいです（直前の段落で持ち上げ空間の超平面の話をしているため）。
* **推奨修正**:
  「元空間（$D$ 次元）の凸包の論理ファセット」であることを用語として厳密に区別してください（例: `site_hull_facet`）。

### 2. API・型定義・エラー設計の整合性

#### (1) `NonFiniteCoordinate` のインデックス仕様
* **仕様**: `NonFiniteCoordinate { index: usize }`
* **指摘**:
  フラット配列 `points: &[f64]` における生の配列添字なのか、それとも「点番号（`0 .. n-1`）」なのかが曖昧です。利用者がデバッグしやすいよう、「何番目の入力点か（あるいは `(point_index, coord_index)`）」を明確に定義してください。

#### (2) `StaticConvexHull<const D: usize>` の API シグネチャ
* **問題点**:
  セクション 9 で静的型が宣言されていますが、メソッド定義が記載されていません。
* **推奨修正**:
  以下のように具体的なシグネチャを記載してください：
  ```rust
  impl<const D: usize> StaticConvexHull<D> {
      pub fn build(points: &[[f64; D]]) -> Result<ConvexHull, ConvexHullError>;
  }
  ```

#### (3) インデックス型の統一（`usize` vs `u32`）
* **指摘**:
  - セクション 3 で「公開インデックスは `u32` のままである」とし、`LogicalFacet.neighbors` や `vertices` は `Vec<u32>` です。
  - しかし `ConvexHull::boundary_cycle(&self, facet: usize)` ではファセット指定に `usize` が使われています。ファセット番号も `u32` に揃えるか、スライスの添字アクセスに合わせて公開 API の引数ルールを統一（`facet: u32` または `facet: usize`）してください。

#### (4) 外部クレート依存の記述矛盾
* **指摘**:
  セクション 1 に「依存リストにない追加クレートでもよい」とありますが、セクション 9 の依存関係には `faer`, `rayon`, `pulp`, `thiserror` の 4 つしか記載されていません。
  任意精度演算（厳密評価のフォールバック）を自作しない場合、`dashu` や `rug`、あるいは `shewchuk-predicates` 相当の外部クレートが必要になります。セクション 9 に「厳密述語のための任意精度または展開クレート（例: `dashu` 等）」を追加するか、「完全インライン自作」とするかを明記すべきです。

### 3. 並列・メモリモデルに関する指摘

#### (1) 並列コミット時の `FacetId` 採番とリマップ
* **指摘**:
  セクション 6 では、ワーカーがローカルに変異を作り、バリア後にインデックス昇順でコミットするとあります。
  ワーカーローカルで生成した新単体が別の新単体を指す場合、コミット前にはグローバルの `FacetId` が確定していません。
  コミット時に「ローカル ID $\to$ グローバル ID」のアドレス付け替え（リマッピング）処理が必須となります。セクション 4 の arena 説明に「コミット時にワーカーローカル ID をグローバル ID へ書き換える」手順を一言補足しておくと、並列コア実装時の迷いがなくなります。

#### (2) Delaunay の対角線決定論性
* **指摘**:
  「逐次と `parallel(true)` は、同じバイナリの上で、正規化後の論理ファセットと Delaunay 単体が一致する」とあります。
  Delaunay において共球な点集合がある場合、挿入順序だけでなく「バッチ内のどのファセットが先に分割されたか」によって対角線の向きが変わる可能性があります。
  並列実行時でも完全に同一の対角線を得るためには、バッチコミット順序だけでなく、**各ファセットの分割アルゴリズム（初期単体の選び方や挿入順）が完全に決定論的（辞書順等で固定）であること**を徹底する必要があります。この点はセクション 6・7 に一貫して強調しておく価値があります。

### 4. 総評

全体の構成は非常に緻密で、数学的・幾何学的な基礎（Euler 特性数による検証、orientation 述語への帰着、退化次元の検出）が強固に組まれています。上記の「$D=1$ の特異処理」「共面点追加の幾何定義の具体化」「依存クレート・API シグネチャの整合」の数点を補正すれば、迷いなく堅牢な実装に入れる完成度の高い仕様書になります。
